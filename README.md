# Skillspace · 中文技能管理器

版本：0.2.0 开发预览版。用于管理 Codex、Claude Code 和 Cursor 技能的 Windows 中文桌面应用。源码、使用说明和测试脚本保存在本仓库。

## 启动

从 [v0.2.0 Release](https://github.com/jonesq211997494/skill-manager/releases/tag/v0.2.0) 下载便携版或 Windows 安装程序，无需 Node.js、Rust 或 WebView2。构建产物未进行商业代码签名。

当前仓库为私有仓库，下载时需要登录有权限的 GitHub 账号。源码仓库不包含安装包，安装包及校验值作为 Release 附件提供。

源码运行可双击 `启动软件.cmd`，或在此目录执行：

```powershell
npm ci
npm run build
npm start
```

开发工具要求：Node.js 24.16 或更高的 24.x，npm 11；依赖由 `package-lock.json` 固定。首次安装 Electron 包时会下载桌面运行时。

## 使用方式

1. 首次进入后点击“开始扫描”，读取三个工具的用户目录及插件目录。在“设置”中检查目录、增加项目或手动来源。
2. 使用名称、中文别名、描述、正文、标签搜索；点击条目查看位置、完整文件清单和 Markdown。收藏和别名只存入管理器数据库。
3. “导入技能”接受根目录包含 `SKILL.md` 的文件夹。选择工具和用户级/项目级范围，生成计划，再确认执行。没有选择工具时可导入独立集中库。
4. 先在“设置 → GitHub 账号”登录，再使用“在线发现”。支持浏览器授权和个人访问令牌；选择仓库中的具体技能后先预览，再安装。
5. “更新”按每个受管理安装的基线、本地和远端比较。两端均有改动时可保留当前版本，或明确选择保存当前快照后使用远端。
6. “操作历史”提供恢复预览。目标后来有改动时阻止普通恢复，可选择先保存当前内容后恢复。

技能文件存在、配置停用状态和工具会话是否加载是分别展示的事实。复制成功后需要由目标工具重新发现；本程序不会运行技能中的脚本。

## 已实现

- 容器递归扫描、物理身份归并、Windows Junction 和符号链接识别、环路/断链报告、扫描预算及取消接口。
- 三工具用户级和已登记项目级目录；系统与插件只读保护；保留 Codex 现有 `skills.config` 停用状态。
- 中文三栏界面、窄窗口详情抽屉、组合搜索与分页、中文别名/标签/收藏/版本固定。
- 完整技能包清单和 SHA-256；PDF、脚本、隐藏文件等支持资料纳入比较；同名差异、路径别名和内容相同分别报告。
- GitHub 仓库检索、来源内目录检索、明确版本解析、斜杠分支校验、固定提交下载、限流/过期缓存/断网提示。
- 受管理复制安装、多工具和多项目安装、批量计划、移除、集中库导入、逐目标结果。
- 安装基线与不可变内容快照、三方文件差异、选择更新、后续修改保护、幂等执行、持久化日志和中断恢复。
- SQLite 一致事务读取旧数据库（包含 WAL），历史清单预览/导入，路径匹配、重复导入幂等和过期会话证据。

## 本轮完善（0.2.0）

- **外部技能也能跟踪来源**：打开详情，选择“关联在线来源”，输入 GitHub 链接，选中对应技能后先比较，再确认关联。关联只保存元数据，不移动、覆盖原文件；可随时解除。
- **更准确的比较**：没有历史基线且内容不同时显示“与来源不同”，不把本地修订直接当成旧版本。内容完整一致后才建立后续三方比较的基线。
- **扫描范围更清楚**：移除目录或项目登记不会删除技能，也不再误报缺失；重新登记后可恢复已有收藏、别名和来源关联。
- **详情及时刷新**：再次打开详情会重新解析最新正文、描述及健康状态。
- **存储统计与取消查询**：设置中可查看应用数据目录用量；扫描、比较、更新检查和来源读取可以取消。自动清理备份仍未启用。
- **文件保护加强**：预览后新增 Git 资料或恢复快照被修改时，执行会停止并保留当前文件。

详见 [审查与改进记录](docs/改进记录-0.2.0.md)。

## 列表版本状态（0.1.2）

“我的技能”和“按工具查看”的版本状态列会显示最新检查结果。点击列表上方“检查更新”，只核验当前筛选范围；勾选技能时只检查筛选范围内的选中项。检查不会安装或替换技能。

| 显示 | 含义 |
| --- | --- |
| 已是最新 | 完整技能包在所示检查时间与远端一致 |
| 有更新 | 远端内容已变化，本地仍等于安装基线 |
| 本地有修改 / 有更新 · 本地修改 | 存在自定义改动，更新前应查看差异 |
| 未检查 / 待复查 | 尚未检查，或来源、文件、基线已变化；24小时以前的结果需要复查 |
| 来源未知 | 尚未手动关联可核验的在线来源，不能按名称推断最新版本 |
| 与来源不同 | 已关联来源但缺少可靠历史基线，只能确认内容不同 |
| 检查失败 / 无法确认 | 来源不可用、文件读取不完整或比较证据不足 |
| 已固定版本 | 用户选择保留当前版本，不表示该版本最新 |

悬停版本文字可查看判断依据和检查时间；“文件正常”及配置状态保留在下方。状态筛选支持最新、有更新、待检查、未知来源、本地改动和失败。系统与插件目录仍只读；没有来源的现有外部技能不会被自动关联到同名仓库；可以在详情中手动确认关联。

## GitHub 登录与限流修复（0.1.1）

推荐在“设置 → GitHub 账号”输入 **GitHub 用户名**，点击“打开浏览器登录”，然后在 GitHub 官方页面完成授权。本机已检测到 Git Credential Manager；其他电脑需安装带该组件的 Git for Windows，才能使用此入口。

也可以在同一位置使用个人访问令牌（PAT）：“创建令牌”会打开 GitHub 官方设置页。公开来源只需读取权限，不需要仓库写权限；请把令牌填入软件的密码框。界面在提交后立即清空输入框。

- 在线搜索、预览与检查更新现在要求登录，不会在凭据无效时退回匿名请求。本地管理仍可离线使用。
- 本程序凭据经 Electron safeStorage 使用 Windows DPAPI 加密后，保存在 `credentials/github.enc`；不写入 SQLite、日志或缓存。加密环境不可用时拒绝保存。
- 浏览器登录由 Git Credential Manager 完成，可能同步保存系统 Git 登录。“退出管理器账号”只清除本程序的加密副本，不删除其他 Git 工具共用的登录。要撤销整个授权，请到 GitHub 的应用授权设置处理。
- 搜索和来源索引优先复用五分钟内的缓存。“从 GitHub 刷新”明确请求新结果；检查更新会主动核验远端分支，并合并同一仓库的重复检查。
- 同一提交的完整技能包再次预览时，先核验本地清单再复用；内容被修改、缺失或增加时重新构建。Git blob 缓存也会校验内容指纹。
- 缓存按账号及凭据身份隔离。切换账号和退出会取消旧请求；401 会失效登录并提示重新验证。
- 配额按仓库/文件和搜索分别展示。发生限流后显示恢复时间与倒计时，冷却内不向 GitHub重复请求。“重试原操作”只用于安全查询，不会自动重放安装或登录。

GitHub 仍可能对已登录账号限流；登录不代表无限请求。配额展示读取最近一次响应，不会为显示状态反复访问 `/rate_limit`。

## 数据位置与恢复

默认数据目录：`%APPDATA%/SkillManagerDesktop`，与旧 `.skills-manager` 独立。

| 路径 | 内容 |
| --- | --- |
| `index.sqlite` 及 WAL/SHM | 技能索引、来源、安装关系、别名标签、计划与日志 |
| `library/` | 按身份和版本分开的集中技能库 |
| `revisions/` | 安装后的完整内容基线 |
| `backups/` | 替换、移除、恢复之前的文件快照 |
| `cache/` | 按账号隔离的在线索引、Git blob 与完整包缓存索引 |
| `credentials/github.enc` | 本程序加密保存的 GitHub 凭据 |
| `staging/` | 下载暂存（由来源模块管理） |

备份管理器数据时请先关闭程序，再整体备份数据目录。仅备份技能文件不能恢复标签、收藏和安装基线。卸载程序默认保留数据与技能。

文件变更前会重新核对包哈希、目录身份和父目录链接。提交前保留快照，在目标同卷暂存并切换。异常中断后启动时检查持久化日志；无法证明前后状态时保留现场并标记“需要恢复”。不要手动删除仍被中断日志引用的快照或 `.skill-manager-*` 暂存目录。

## 当前限制

这是可运行的开发预览版，尚未达到原文档全部 V1 发布验收条件，详情见 [验收记录](docs/验收记录.md)。

- 使用 Electron、React、TypeScript、Node.js 和 SQLite。原文档的 Tauri/Rust 为建议选型；本机未安装 Rust，故采用已具备的工具链交付可执行桌面程序。
- 三工具的真实会话发现、同名优先级和刷新时机未完成全矩阵联调。原生配置写入/停用保持不可用；现有停用只读显示。
- 只修改本程序建立的安装；外部来源关联只提供比较，不允许覆盖或移除原文件。重复分析不会自动删除“相同内容”的跨工具副本。
- 含包内链接或无法完整核验的包禁止自动复制安装。目标内含 Git 工作区时禁止覆盖或移除，避免损坏版本库。
- 已登录的 GitHub 接口仍受服务端额度限制。大型来源可能无法一次完成下载；限制会明确报告。私有仓库兼容性尚未单独验收，包外依赖不自动迁移。
- 来源内搜索主要索引技能目录名称，完整元数据在预览选中技能时读取。二进制和大于 512KB 的文件以清单摘要比较。
- 支持手动用量统计及快照容量阈值提示。保留偏好可以保存，但没有后台自动清理；程序不会按保留天数擅自删除快照。外部集中库位置会明确提示未包含在应用目录统计中。
- 暂无文件系统实时监控，请使用刷新扫描；全部数据索引保存在 SQLite 中，搜索在应用内存中完成。
- 未在干净虚拟机完成安装、卸载及 Windows 150% 系统缩放的完整测试；没有商业签名和自动更新。

## 开发与验证

```powershell
npm test                 # 临时目录中的核心与集成测试
npm run build            # TypeScript 检查与前端构建
npm run test:desktop     # Electron 隐藏窗口与三个尺寸截图
node scripts/ui-flow.mjs # 桌面交互闭环
node scripts/github-ui-smoke.mjs # 隔离认证、加密保存、缓存与限流UI测试
node scripts/benchmark.mjs
npm run package          # Windows 便携版与 NSIS 安装程序
```

`test-results/` 保存实际执行结果；`.runtime/` 是验证数据。这些目录仅在本机生成，不纳入 Git。测试不改动用户现有技能和工具配置。

提交到 `main` 或创建 Pull Request 时，GitHub Actions 会在 Windows 环境运行核心测试和界面构建。Release 的发布说明位于 `docs/releases/`。
