# 实现说明

## 技术选择

本机具备 Node.js 24、npm 和 Python，没有 Rust 工具链。选用 Electron 44、React 19、TypeScript 5、Vite 7 和 Node 内置 SQLite，交付可直接运行的 Windows 桌面程序。此项是对原设计“建议技术选型”的实现调整，不改变本地文件与操作恢复边界。

界面没有 Node 权限；通过固定 IPC 通道调用应用服务。主进程检查请求来自自己的主窗口和主框架，启用 sandbox、contextIsolation 与 webSecurity，拒绝任意页面导航、权限请求和新窗口。Markdown 不解析原始 HTML；网页链接仅经校验后由系统浏览器打开。

## 状态与数据

SQLite 中使用带版本的集合记录：`skills`、`metadata`、`roots`、`projects`、`sources`、`deployments`、`plans`、`operations`、`observations`、`migrations` 等。集合内以稳定主键保存 JSON，索引与文件正文分开。各工具/范围/目录拥有独立安装记录，不使用技能名称唯一约束。

扫描器用卷与目录标识归并物理实体，保留每个显示路径。受管理更新替换目录后，服务层保留旧逻辑ID及别名、收藏、标签；新实体身份仍重新采集。来源URL、仓库ID、提交、技能子目录、包哈希和安装基线分别保存。

默认先读元数据，在详情、重复分析和写操作时计算完整清单。规范化相对路径、类型、大小和内容摘要参与包指纹。只排除 `.git` 内部数据；外部链接、读取不完整或超限不会产生“完全相同”结论。

## 可恢复操作

1. 生成包含来源、目标、共享影响、前置实体与内容指纹的持久计划。
2. 执行时再次检查目标和来源，计划超过30分钟要求重新预览。
3. 复制当前内容到独立备份区并校验；保存新版本不可变基线。
4. 在目标同卷建立暂存目录，完整复制并校验；再次核对计划。
5. 持久记录切换开始，原目录改名为保留现场，然后切换新目录。
6. 核验目标清单，事务更新安装记录；删除前再次核对已备份现场。

多个目标分别提交，不承诺全批次原子成功。一个应用实例内的写操作串行；同一计划重试返回原操作。重启根据实际指纹收尾、恢复原目录，或保留现场等待处理。

恢复是新的操作，也会保存当前内容。后续编辑默认阻止恢复；用户选择另存后恢复才能继续。SQLite 与文件系统不被描述为一个原子事务。

## 未实现的增强项

不进行后台无人值守更新、自动冲突合并、自动删除重复包、原生启停配置写入、实时目录监控或备份自动清理。配置中可保存备份偏好，所有现有快照仍保留。未来增量工作应先补齐验收记录中的真实工具、跨盘、低空间、系统缩放和干净环境安装测试。


## 0.1.1 GitHub 身份与缓存

GitHubAuth 只在主进程使用凭据。状态跨IPC返回账号摘要和能力，不返回Token。浏览器登录使用本机Git Credential Manager的固定参数命令，用户明确输入目标账号；完成后核验 `/user` 返回账号。PAT由同一端点验证后加密存储。程序启动只解密自身文件和检测组件版本，不枚举系统Git账号。

SourceService 每个操作捕获身份与取消信号，认证头只发送给 `api.github.com`，外域重定向被拒绝。401不会触发匿名重试；登录变化取消旧队列和在途结果。缓存命名空间以身份摘要分开，不在缓存记录中保存凭据。

元数据缓存的有效期为五分钟，强制刷新绕过有效期。固定提交包按仓库ID、提交和子目录复用，但每次复用都核验全文件集合、大小、SHA与链接边界。相同内容跨分支复用时仍保留各次安装所选跟踪引用。下载失败可复用先前已核验的blob，避免重复消耗额度。

限流分别记录搜索、核心配额及二级全局冷却；遵循Retry-After、reset和最低等待时间。请求串行化，相同查询与下载共享在途结果。进程内冷却阻止重复请求；重启后的首个网络请求会重新取得服务端配额信息。

Electron contextBridge 不保证保留Error自定义字段，因此预加载层用结构化失败对象传输code/details，再由渲染层创建错误；恢复时间与登录失效码可完整到达界面。
