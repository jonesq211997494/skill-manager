# 0.2.0 审查与改进记录

## 本轮处理

| 问题 | 用户影响 | 本轮改动 |
| --- | --- | --- |
| 外部技能没有来源关联入口 | 大量现有技能一直是来源未知，版本状态无法使用 | 新增手动选源、完整比较、确认关联和解除关联；关联不产生文件写入权限 |
| 不同内容缺乏可靠历史基线 | 容易把本地修改误认为旧版本 | 使用“与来源不同”表达两方比较；完整一致后才建立可靠基线 |
| 详情只刷新 raw | 源码和正文可能显示不同版本 | 重新解析正文、元数据与健康状态，并保留用户的管理元数据 |
| 根目录移除和部分扫描混淆 | 未扫描的技能被误报丢失，别名或只读归属丢失 | 按每个根的完成状态协调索引；取消登记隐藏记录，重新登记恢复原身份 |
| 外部目录原子替换改变 inode | 别名、收藏和来源关联断开 | 同规范物理路径保留管理 ID，实体变化使旧检查证据失效 |
| 同类查询无条件共享结果 | 不同来源预览可能收到别的任务结果 | 同类任务进行中明确提示忙，来源请求层仍对真正相同的请求去重 |
| 查询期间关联变化 | 已解绑来源可能被迟到结果恢复 | 写回前核验当前关联修订、来源和扫描状态 |
| 容量设置只有偏好 | 用户无法了解快照占用 | 增加只读用量统计和实际阈值提醒，仍不自动删除文件 |
| 预览后新增 Git 资料 | 执行可能忽略新建的 Git 工作区 | 切换和清理前再次检查，保留原件与现场 |
| 恢复快照被修改 | 可能将损坏快照恢复到有效目录 | 计划及执行绑定原操作的快照指纹 |

## 仍建议继续完善

1. **用户整理数据的导出和导入**：让标签、收藏、来源关联和项目配置可迁移；账号凭据应单独处理，不能混入普通导出文件。
2. **备份清理计划**：先列出快照、引用关系和可释放空间，再由用户确认；未完成操作依赖的快照必须保留。
3. **真实工具联调**：针对 Codex、Claude Code、Cursor 的具体版本验证会话发现和配置生效；通过后再开放原生启停。
4. **增量刷新与性能基准**：先记录真实大目录场景，再加入去抖的文件监控和索引查询优化，避免每次刷新计算全部附件哈希。
5. **发布自动化**：将签名、干净 Windows 安装验证和版本升级回归纳入后续发布流程。

这些后续项尚未实现，不以设置项或成功提示替代实际能力。本轮测试以隔离目录和模拟网络进行，真实技能源文件没有被本次开发修改。
