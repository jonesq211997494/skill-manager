## 关键失败用例

- 引擎成功后让扫描、目录登记或刷新日志失败，检查文件、操作记录及前端提示仍一致。关闭确认框后读取界面数据再次失败，也保留同一个成功操作。只刷新后确认文件执行次数没有增加。
- 相同计划重复提交、并发提交错误摘要、手动与自动刷新交叠，以及刷新期间操作被恢复，分别验证幂等、摘要校验和最新日志保留。
- 在真实更新的快照完成、暂存复制完成、首次目录切换、元数据提交四个阶段请求退出。目标与快照内容、部署基线、持久日志一致；重开无需回滚已完成事务。
- 非法整理和设置参数在目录读取、网络配置或持久化前失败，原数据不发生部分改写。有效设置关闭并重开后仍为 number；历史数字字符串也统一规范。
- Chromium 中实际注入内联脚本、外域图片和 fetch 请求，验证 CSP 阻止执行或发送。Markdown 正常粗体、列表和代码仍可显示，原始 HTML、图片请求和危险协议受限。
- Windows Junction 指向未登记目录时不能通过 `files.open` 打开包外内容。用户明确登记该链接根后，仅允许其真实范围。
- 当前数据库版本重复启动、过新版本、缺失或歧义版本及非法 JSON 均有回归。版本保护不等于完整数据库迁移或恢复集备份。

新增行为先运行失败用例再实现。核心结果、生命周期及数据库保护的失败基线均已实际观察；后续修复并发刷新覆盖的两项用例也先失败再通过。

## 兼容与剩余范围

- `operations.execute` 新字段是增量接口；旧调用者仍可读取顶层 id/status。新增界面依据 `operation.status` 描述文件结果，不能将 `indexRefresh.failed` 当作安装失败。
- 新 IPC 契约会拒绝以前被静默截断、过滤或隐式转换的载荷，错误统一为稳定代码及字段位置。合法界面参数保持兼容。
- 正常退出没有强行超时关库。不可取消的已受理调用需要完成后才能退出；Windows 关机、注销和强杀仍可能绕过退出事件，原有持久化恢复继续保留。
- 数据库启动检查会将主文件与已有 WAL 复制到临时目录，并在检查前后核验源文件未变；临时目录需要相应空间和写入权限。该副本用于预检，不是恢复备份。未做数据库结构升级：逐级迁移、迁移前完整备份与迁移中断验证属于 I05 后续任务。
- I06 整理数据导出导入、完整恢复备份和 I07 引用感知手动清理尚未开放；不删除快照、基线或暂存现场。
- I08 三工具不同版本与真实会话发现、I10 全链路大规模性能、I11 完整查询取消登记和 I12 脱敏诊断包仍需独立实施。
- 未验证干净 Windows 安装、卸载保留数据、跨版本安装器升级、真实进程强杀、断电或全量系统缩放矩阵。打包候选启动不能替代这些验收。构建产物仍未签名，没有启用自动更新。
- GitHub Actions 产物留存尚未启用。若后续获准，应仅上传经过核验的合成数据报告与必要截图，限定保留期限，不上传数据库、完整配置、技能正文或凭据。
